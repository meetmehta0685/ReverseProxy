Files and responsibilities

cmd/proxy/main.go
Process boundary: flags, logger, proxy construction, HTTP server configuration, OS signals, graceful shutdown.
internal/proxy/proxy.go
Request boundary: configuration validation, routing, forwarding, middleware, deadlines, transport setup, and response tracking.
internal/proxy/circuit_breaker.go
Closed/open/half-open state, cooldown, single-probe recovery, and stale-request protection.
internal/proxy/rate_limiter.go
Process-local fixed-window request limiter and retry timing.
internal/proxy/metrics.go
Atomic counters and Prometheus text exposition.
internal/proxy/proxy_test.go
Behavioral evidence: forwarding, correlation IDs, local endpoints, rate limiting, circuit breaking, timeouts, and configuration validation using HTTP test utilities.
go.mod
Module identity and minimum Go language/toolchain version; there are no third-party dependencies.

Request journey

Client→Proxy→Backend

The proxy is a server to the client and a client to the backend. Every request enters correlation logging first; local paths /healthz and /metrics stop in route selection, while every other path enters the guards and forwarding.

Glossary seed

Client
The participant that sends a request.
Origin server
The authoritative server for a target resource.
Backend / upstream
This project's configured server that receives forwarded requests.
Reverse proxy / gateway
An intermediary that appears to be the origin to clients, then forwards requests to another server.
Handler
A Go value with ServeHTTP(ResponseWriter, *Request).
Middleware
A handler wrapper that adds behavior before or after another handler.
Transport
The client-side machinery that obtains a connection, sends an HTTP request, and receives its response.
