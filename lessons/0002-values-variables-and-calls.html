Values, variables,
and calls

A function call is an action. A variable is a name you keep so you can use a result later. This is the small engine driving main.go.

A value is data

These are values:

"8080"       // text
15*time.Second // a duration value
true           // a boolean value

Values are the things a program can pass around, store, compare, or give to a function. Their exact types matter, but we’ll learn types gradually.

A variable gives a value a name

message := "hello"
message = "goodbye"

:= means “create a new variable and put this value in it.” The later = means “replace the value in an existing variable.”

Read the two lines as: create message with "hello", then replace its value with "goodbye".

Retrieval check

What does the second line do?

A function call performs work

flag.Parse()

This calls the Parse function belonging to the flag package. The parentheses mean “run it now.” Empty parentheses mean this call supplies no arguments.

With arguments, the values go inside the parentheses:

flag.String("listen", ":8080", "address to bind")

Read this as “call String from flag, giving it three values.” The function returns a result, and := gives that result a name:

listen := flag.String("listen", ":8080", "address to bind")

We’ll explain the result’s pointer shape later. For now, recognize the pattern: call a function → save what it returns.

Find the pattern in this project

At the start of main, the project creates four named values from command-line flag functions:

listen := flag.String(...)
backend := flag.String(...)
rateLimit := flag.Int(...)
upstreamTimeout := flag.Duration(...)

Then it calls:

flag.Parse()

Only after parsing does the program construct the proxy using the chosen configuration. The order matters: first define the available settings, then read the user’s settings, then build the service.
