Pointers are
addresses

The asterisk looks intimidating, but in this project it answers one simple question: “Do I have the value, or a way to find the value?”

Two things can be named

Imagine a mailbox. The value is the letter inside. The address tells you which mailbox to open.

name := "Go"  // name holds the value itself

ptr := &name   // ptr holds name's address

The & operator means “give me the address of this variable.” A pointer is a value that holds an address.

Reading through the address

name := "Go"
ptr := &name
word := *ptr

The * before ptr means “follow the address and read the value there.” After these lines, word contains "Go". We call this dereferencing.

Retrieval check

After name := "Go"; ptr := &name; word := *ptr, what is in word?

Why flags return pointers

Look at this line in main.go:

listen := flag.String("listen", ":8080", "address to bind")

flag.String returns a pointer to the setting. After flag.Parse(), Go updates the value at that address if the user supplied -listen. The variable listen still points to the same place; the value there may have changed.

server := http.Server{
    Addr: *listen,
}

Here *listen means “read the string stored at the address.” The server wants the string itself, such as ":8080", rather than the address.

Why methods sometimes use *Proxy

func (p *Proxy) ServeHTTP(...) { ... }

This says the method receives a pointer to a Proxy. It can work with the original proxy object rather than a copied proxy. That matters because the proxy contains shared counters, a limiter, and a circuit breaker. We’ll return to copying and shared state when we study concurrency.
