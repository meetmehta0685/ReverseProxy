# Mission: Master the Go Reverse Proxy

## Why
Become able to explain this project convincingly in interviews, rebuild its core from memory, and confidently modify, debug, deploy, and operate it as a real network service.

## Success looks like
- Trace any request through the proxy and explain every important line involved
- Rebuild the proxy incrementally without copying the implementation
- Explain the Go, HTTP, networking, concurrency, resilience, observability, and testing concepts in interviews
- Diagnose failures and safely extend or productionize the service
- Recognize the current design's guarantees, tradeoffs, limitations, and security risks

## Constraints
- This is the learner's first experience with Go; introduce syntax before framework or networking abstractions
- Start from first principles; do not assume hidden Go or HTTP knowledge
- Use short lessons, retrieval practice, experiments, and progressively harder implementation tasks
- Ground technical claims in Go documentation, standards, and other primary sources

## Out of scope
- Implementing unrelated network protocols from scratch
- Distributed infrastructure not needed to understand or evolve this repository
